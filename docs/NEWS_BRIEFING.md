# 뉴스 브리핑 평가

WebIQ 뉴스 검색만으로 음성 뉴스 브리핑을 만들고, 기존 뉴스 공급(헤드라인 낭독 등)을 대체할 수 있는지
시나리오로 확인한다. 이 화면은 WebIQ만 실행하며 Grounding with Bing과 비교하지 않는다.

## 실행 방법

1. 왼쪽 메뉴에서 **뉴스 브리핑**을 연다.
2. 시나리오를 고른다.
3. **이 시나리오 실행**(3문항) 또는 **전체 실행**(6개 시나리오, 18문항)을 누른다. 질문마다 WebIQ 검색과 음성 생성 비용이 든다.
4. 결과 카드에서 **기사 내용과 일치**와 **듣기 길이**를 평가한다.
5. **평가 요약**에서 집계를 확인하고 CSV 또는 보고서(Markdown)를 내려받는다.

질문을 직접 입력하거나 말해도 된다. 질문이 지금 고른 시나리오의 질문과 같으면 그 문항의 결과로 기록한다.
다르면 자유 질문으로 기록하고 진행률에는 넣지 않는다.

음성 처리 방식은 설정에서 적용한 방식(Agent 연결 또는 End-to-end)을 따른다. GPT-Live가 적용되어 있으면
Agent 연결로 실행한다. GPT-Live는 텍스트 질문을 받지 않아 정해진 질문을 보낼 수 없기 때문이다.

## 브리핑 설정

설정 패널의 **뉴스 브리핑** 항목이다. 음성 설정과 같이 **적용**을 눌러야 반영된다.
앱은 이 값을 `[뉴스 브리핑 규칙]` 글로 바꿔 대화를 시작할 때 맥락 메시지에 넣는다.
Agent 연결에서는 WebIQ Agent가, End-to-end에서는 선택한 모델이 이 규칙을 받는다.

| 항목 | 선택(기본값 굵게) | 규칙 |
| --- | --- | --- |
| 기사 기간 | **최근 24시간**, 최근 7일, 기간 제한 없음 | 뉴스 검색 도구에 기간을 지정하도록 요청한다 |
| 브리핑 기사 수 | 3건, **5건**, 10건 | 서로 다른 기사를 이 수 안팎으로 고른다 |
| 답변 길이 | 30초 이내, **1분 이내**, 제한 없음 | 30초는 한국어 약 150자, 1분은 약 300자 |
| 언론사·게시 시각 말하기 | **말하기**, 생략 | 기사마다 언론사 이름과 게시 시각을 말한다 |
| 같은 사건 기사 묶기 | **묶기**, 따로 | 같은 사건을 다룬 기사를 하나로 묶는다 |

모든 브리핑에는 "검색 결과에 없는 내용은 추측하지 않고, 기사가 부족하면 부족하다고 말한다"는 규칙이 붙는다.

## 시나리오

시나리오 1–5는 질문마다 새 연결을 연다. 시나리오 6은 "오늘 주요 뉴스 브리핑해줘"로 먼저 브리핑을 받고,
같은 대화에서 이어서 묻는다. 먼저 받은 브리핑은 "앞선 브리핑"으로 기록하고 진행률에는 넣지 않는다.

| 시나리오 | 확인하는 것 | 평가 기준 | 질문 |
| --- | --- | --- | --- |
| ① 헤드라인 브리핑 | 기존 뉴스 공급사의 헤드라인 낭독을 대체할 수 있는지 | 최신성, 분야 다양성, 답변 길이, 출처 말하기 | 오늘 주요 뉴스 브리핑해줘 / 아침 뉴스 1분 요약해줘 / 지금 가장 많이 보도되는 뉴스 뭐야? |
| ② 분야별 뉴스 | 요청한 분야의 최신 기사를 요청한 수만큼 고르는지 | 분야 일치, 최신성, 기사 수 지키기 | 오늘 경제 뉴스 3개 알려줘 / IT·AI 최신 소식 알려줘 / 어젯밤 프로야구 결과 기사 알려줘 |
| ③ 관심 주제 추적 | 주제에 맞는 기사를 기간 안에서 여러 언론사로 찾는지 | 주제 일치, 기간 지키기, 언론사 다양성 | 지난 일주일 전기차 보조금 기사 찾아줘 / 반도체 수출 관련 최신 소식 있어? / 이번 달 유가 전망 기사 알려줘 |
| ④ 경로·지역 소식 | 지역에 맞고 이동에 도움이 되는 기사를 고르는지 | 지역 일치, 최신성, 이동 관련성 | 부산 가는 길에 경부고속도로 관련 소식 있어? / 오늘 서울 도심 교통 통제 기사 알려줘 / 강릉 이번 주말 축제 소식 있어? |
| ⑤ 속보·방금 발표 | 게시 시각을 확인하고, 발표 전 예상 기사와 결과 기사를 구분하는지 | 1시간 이내, 게시 시각, 예상·결과 구분 | 지금 속보 있어? / 오늘 기준금리 결정 결과 나왔어? / 방금 발표된 정부 발표 내용 알려줘 |
| ⑥ 이어지는 대화 | 앞 답변의 기사를 기억하고 같은 기사를 다시 찾는지 | 문맥 유지, 같은 기사 찾기, 언론사 비교 | 방금 두 번째 기사 더 자세히 / 그 뉴스 다른 언론사는 뭐라고 해? / 그거 언제부터 시행된대? |

## 측정값

결과 카드와 평가 요약은 다음 값을 보여 준다. 사람 평가를 뺀 값은 브라우저가 검색 결과와 답변 글에서 자동으로 계산한다.

| 값 | 계산 |
| --- | --- |
| 응답 시작 | 질문을 보낸 때부터 답변 음성이 시작될 때까지 걸린 시간 |
| 가장 최신 기사 | 검색 결과 중 게시 시각이 가장 최근인 기사의 경과 시간 |
| 기간 이내 | 게시 시각이 있는 검색 결과 중 기사 기간 안에 든 비율. 기간 제한이 없으면 계산하지 않는다 |
| 언론사 수 | 검색 결과에 나온 서로 다른 언론사 수 |
| 언론사·시각 언급 | 답변에 검색 결과의 언론사 이름과 게시 시각 표현("2시간 전" 등)이 둘 다 있는지 |
| 사람 평가 | 기사 내용과 일치(일치, 일부 다름, 틀림), 듣기 길이(적당, 너무 김, 너무 짧음) |

평가 요약은 문항마다 가장 최근에 끝난 결과로 집계한다. 시나리오 판정은 다음과 같다.

- **진행 중:** 세 문항을 모두 실행하지 않았다.
- **보완 필요:** 사람 평가에 "일치"가 아닌 문항이 있거나, 기간 이내 비율 평균이 80% 미만이다.
- **평가 필요:** 위 조건에 해당하지 않지만, 사람 평가를 하지 않은 문항이 있다.
- **기준 충족:** 세 문항 모두 실행했고, 모두 "일치"로 평가했고, 기간 이내 비율 평균이 80% 이상이다.

**기존 뉴스 공급사 기준값**(헤드라인 갱신 주기, 제공 분야 수, 게시 → 제공 지연, 제공 언론사 수)을 입력하면 보고서에 함께 적는다.

## 기록 보관

기록과 기준값은 이 브라우저의 로컬 저장소에만 둔다(기록은 최근 300건). 서버에는 저장하지 않는다.
다른 브라우저나 기기에서는 보이지 않으므로, 결과를 남기려면 CSV나 보고서를 내려받는다.
**기록 지우기**는 이 브라우저의 기록을 지운다.
